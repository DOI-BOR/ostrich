Algorithms - Bisection

The OSTRICH bisection optimization algorithm

Initial Publication:

April 11, 2021

Modified:

November 1, 2026

The following optional group will configure the bisection algorithm and will be processed if [ProgramType] is set to “BisectionAlgorithm”. 

BeginBisectionAlg
MaxOuterIterations [max_outer]
MaxInnerIterations [max_inner]
EndBisectionAlg

BeginBisectionAlg
MaxOuterIterations 50
MaxInnerIterations 20
EndBisectionAlg

Figure 1: General Format (left) and Example (right) of the Bisection Group

Where BeginBisectionAlg and EndBisectionAlg are parsing tags that wrap the following set of algorithm configuration variables:

  • MaxOuterIterations: The number of outer iterations of the algorithm. One outer iteration corresponds to application of the bisection method to every parameter, one parameter at a time. The first outer iteration starts from the initial parameter values, and each subsequent outer iteration starts from a randomly chosen parameter set. The value must be greater than zero. The default value is 50.
  • MaxInnerIterations: The number of inner iterations applied to each parameter. Each inner iteration reduces the searchable parameter range by 50%. The value must be greater than zero. The default value is 20.
  • ConvergenceVal: This value is accepted for compatibility with previous versions of OSTRICH and is reported in the algorithm metrics, but it is not currently used to stop the search early. The default value is 1.00E-6.

The following behaviors apply to the bisection algorithm in the development version of OSTRICH:

  • Search procedure: Each parameter is searched while all other parameters are held at their current values. The parameter's range is first divided into four quadrants by evaluating the lower bound, upper bound, quarter-point, mid-point, and three-quarter-point. Each inner iteration keeps the half of the range around the best point and evaluates two new quarter points, plus a new mid-point when the best point is at the edge of the range. A parameter's new value is kept only if it improves on the best objective found so far; otherwise its previous value is retained.
  • Parallel evaluation: The points evaluated at each step of the search are independent of one another and are distributed across the available workers. Five points are evaluated at the start of each parameter's search and two or three points at each inner iteration, so the run time will not be reduced further by using more than five workers.
  • Number of evaluations: The search requires at least 1 + MaxOuterIterations × (number of parameters) × (5 + 2 × MaxInnerIterations) model evaluations.
  • Output: The OSTRICH run record reports the best solution found after each outer iteration. Because later outer iterations start from random parameter sets, the reported solution is always the best one found so far rather than the starting point of the current outer iteration. The objective function of every evaluation is recorded in the OstModelN.txt file of the processor that evaluated it.
  • Warm start: WarmStart is not yet supported for the bisection algorithm. If WarmStart is set to yes, the analysis will stop with an error.
  • Least-squares calibration: The bisection algorithm currently runs in optimization mode only.
