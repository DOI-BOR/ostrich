Algorithms - Sampling Algorithm (Big Bang - Big Cruch)

The OSTRICH sampling optimization algorithm

Initial Publication:

April 11, 2021

Modified:

November 2, 2026

The following optional group will configure the Big Bang – Big Crunch (BB-BC) algorithm and will be processed if [ProgramType] is set to “SamplingAlgorithm”. 

BeginSamplingAlg
MaxEvaluations  
EndSamplingAlg

BeginSamplingAlg
MaxEvaluations      100
EndSamplingAlg

Figure 1: General Format (left) and Example (right) of the BB-BC Group

Where BeginSamplingAlg and EndSamplingAlg are parsing tags that wrap the following set of algorithm configuration variables:

  • MaxEvaluations: The computational budget. The default value is 100, and values less than 1 are reset to 1. The budget is divided into sqrt(MaxEvaluations) iterations (rounded down) with MaxEvaluations / iterations samples per iteration (rounded down). Any remaining evaluations are added to the initial Latin Hypercube sample. For example, a budget of 50 evaluations results in 7 iterations of 7 samples, with 1 extra initial sample.

The following behaviors apply to the sampling algorithm in the development version of OSTRICH:

  • Parallel evaluation: The algorithm runs in parallel. The initial Latin Hypercube sample and the samples of each subsequent iteration are created together and distributed across the available workers. Once an iteration has been evaluated, its results are used in order to update the best solution and the search directions. Consecutive samples within an iteration use opposite search directions, reproducing the sequence of the serial algorithm for an iteration in which the best solution does not improve.
  • Output: The best solution and the relative change (in percent) of the best objective are reported in the OSTRICH run record after each iteration. The objective function of every sample is recorded in the OstModelN.txt file of the processor that evaluated it.
  • Warm start: If WarmStart is set to yes, the analysis resumes at the iteration after the last one in the OSTRICH run record, starting from the best solution found in the OstModelN.txt files. If Caching is set to yes, previously evaluated parameter sets are not solved again. The search directions cannot be recovered and are reset to their initial values.
  • Initial parameter sets: User-defined parameter sets supplied in a BeginInitParams/EndInitParams group are not yet supported and are ignored.
  • Calibration statistics: Calibration statistics are not yet computed when the objective function is WSSE.

References

Erol, O. K.,Eksin, I. 2006. A new optimization method: Big Bang-Big Crunch. Advances in Engineering Software 37, 106-111.
