Algorithms - Parallel PADDS

The OSTRICH Parallel Pareto Archived DDS multi-objective optimization algorithm

Initial Publication:

April 11, 2021

Modified:

November 8, 2026

The following optional group will configure a parallelized version of the PADDS algorithm and will be processed if ProgramType is set to “ParaPADDS”. 

BeginParallelPADDSAlg
PerturbationValue      [r_val]
MaxIterations          [budget]
SelectionMetric        [metric]
EndParallelPADDSAlg

BeginParallelPADDSAlg
PerturbationValue      0.2
MaxIterations          50
SelectionMetric        Random
EndParallelPADDSAlg

Figure 1: General Format (left) and Example (right) of the parallel PADDS Group

Where BeginParallelPADDSAlg and EndParallelPADDSAlg are parsing tags that wrap the following set of algorithm configuration variables:

  • PerturbationValue: This parameter defines the standard deviation of the decision variable perturbations as follows: PerturbationValue = StdDev / DV_Range. The allowable range is 0 to 1. As the value increases, the sampling becomes more and more spread out from the current best value of the decision variable. The default and recommended value is 0.2.
  • MaxIterations: The computational budget in terms of the number of objective function evaluations. Users need to set this input for each problem according to how long each objective function evaluation takes and how quickly an answer is needed. The more objective functions you use, the better your estimate of the globally optimal solution will be. The default value is 50.

  • SelectionMetric: This metric for scoring non-dominated solutions when seeding DDS trials within the overall PADDS algorithm. Values currently supported are listed below:

    • Random
    • CrowdingDistance
    • EstimatedHyperVolumeContribution
    • ExactHyperVolumeContribution

    The default selection metric value is “ExactHyperVolumeContribution”. For a discussion on choosing the appropriate selection metric see Asadzadeh and Tolson (2013).

Other acceptable parsing tags are:

  • BeginParallelPADDS and EndParallelPADDS
  • BeginParaPADDSAlg and EndParaPADDSAlg
  • BeginParaPADDS and EndParaPADDS
  • BeginPADDSAlg and EndPADDSAlg
  • BeginPADDS and EndPADDS

The following behaviors apply to the parallel PADDS algorithm in the development version of OSTRICH:

  • Batch evaluation: Candidates are generated in batches, one for each worker (plus one if SolveOnPrimary is enabled), from the current archive. Each batch is solved concurrently, and the candidates are then added to the archive in the order they were generated. Each candidate is compared against the solution it was generated from. A batch completes when its slowest model run completes.
  • Initialization: The search begins with max(0.5% of MaxIterations, batch size) uniformly random solutions, limited so that MaxIterations is not exceeded. Every decision variable is perturbed for search evaluations up to twice the batch size. Initial parameter sets (BeginInitParams) are not used.
  • Objectives: The objectives are the weighted sum of squared errors (WSSE) of each observation group, so the ObjectiveFunction must be WSSE and each objective requires its own observation group. Other objective functions (e.g. GCOP) are not yet supported.
  • Duplicates and integer parameters: A candidate whose objectives match those of a non-dominated solution is discarded as a duplicate. Integer parameters are rounded before evaluation, and the rounded values are archived and reported.
  • Output: Each time a new non-dominated solution is found, the non-dominated solutions are written to the run record in OstOutput0.txt and to OstNonDomSolutions0.txt. The perturbation probability of each search evaluation is written to OstPADDSPn.txt, and the objectives of the final non-dominated solutions are written to c_results.txt. The final non-dominated and dominated solutions and the algorithm metrics are written at the end of the analysis.
  • Warm start: The WarmStart option is not available for parallel PADDS. A warning is logged and a new analysis is performed.
  • Not yet supported: The PreserveBestModel option is not available for multi-objective algorithms. A warning is logged and the option is disabled.
